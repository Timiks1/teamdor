# teamdor — сайт студії

Сайт за ТЗ v1 (`spec.md`): Astro (статичні сторінки + серверний роут для форми), UA/EN, адмінка Sveltia CMS.

## Запуск

```bash
npm install
npm run dev        # http://localhost:4321 — розробка
npm run build      # збірка в dist/
```

Налаштування — у `.env` (зразок: `.env.example`): адреса сайту, GA4, SMTP для заявок, вебхук CRM.

## Структура

| Що | Де |
|---|---|
| Весь контент (тексти, ціни, кейси, FAQ, контакти) | `content/uk/*.json`, `content/en/*.json`, `content/contacts.json` |
| Юридичні сторінки | `content/{uk,en}/legal/*.md` → `/privacy`, `/offer`, `/cookies` (+ `/en/...`) |
| Блоки головної | `src/components/*.astro` (порядок — `HomePage.astro`) |
| «Етапи» (6 етапів; двері з лего збираються прокруткою, як відео; фізика без перетинів) | `src/components/Stages.astro`, сцена — `src/lib/lego/door.js` |
| «Що робимо» і «Автоматизація» | `src/components/Services.astro`, `Automation.astro`, збірки — `src/lib/lego/builds.js` |
| Рушій лего-деталей (three.js) | `src/lib/lego/kit.js`, спільний рендерер карток — `src/lib/lego/shelf.js` |
| Форма → email / CRM | `src/pages/api/lead.ts`, `src/lib/lead.ts` |
| Кольори, шрифти, кнопки | `src/styles/global.css` |
| Адмінка | `public/admin/` → `/admin` |

## Лего-ілюстрації (дод. ТЗ v0.2)

- three.js вантажиться ліниво, лише коли блок з деталями наближається до екрана; перший екран його не чекає.
- Для кожної сцени є статична PNG у `public/img/lego/` (той самий кадр): видно до завантаження і якщо WebGL недоступний.
  Після зміни збірок у `builds.js` / `door.js` PNG треба перегенерувати (відрендерити сцени тим самим рушієм і зберегти кадри).
- Усі картки послуг малює один WebGL-рендерер; поза екраном нічого не крутиться; «зменшити рух» — статичний кадр.
- Шрифти Fixel урізані до латиниці й кирилиці (≈30 % легші). Якщо в текстах з'являться інші символи — перегенерувати з оригіналів.

## Адмінка

`/admin` — Sveltia CMS: правка всіх текстів, цін, кейсів, FAQ і контактів обома мовами, зручно з телефона.
Працює через Git: кожне збереження — коміт у репозиторій, хостинг перезбирає сайт.

1. Залити проєкт у GitHub-репозиторій.
2. Репозиторій уже вказано в `public/admin/config.yml` (`Timiks1/teamdor`).
3. Вхід — через GitHub (для Netlify/Vercel/Cloudflare Pages є готові OAuth-схеми, див. документацію Sveltia CMS).

## Форма заявки

- Поля: ім'я, телефон, email (обов'язкові), месенджер, коментар.
- Антиспам: приховане поле-пастка, перевірка часу заповнення, ліміт 5 заявок / 10 хв з однієї IP.
- Лист на `MAIL_TO` через SMTP. Без `SMTP_HOST` заявка лише пишеться в лог (для розробки) — **на продакшні SMTP обов'язковий**.
- CRM: задати `CRM_WEBHOOK_URL` — заявка дублюється туди JSON-ом. Інші канали — додати функцію в `CHANNELS` (`src/lib/lead.ts`).
- Без JavaScript форма теж працює (редирект на `/thanks`).

## Аналітика й cookies

GA4 (`PUBLIC_GA_ID`) вантажиться лише після «Прийняти» в cookie-банері. Події: `form_submit`, `cta_click` (усі кнопки з `data-cta`).

## Хостинг

Vercel (адаптер `@astrojs/vercel`): підключити репозиторій у Vercel — він сам збирає сайт після кожного пушу, зокрема після змін з адмінки.
Змінні оточення (`SITE_URL`, `PUBLIC_GA_ID`, `SMTP_*`, `MAIL_*`, `CRM_WEBHOOK_URL`) задаються в Vercel → Settings → Environment Variables.

## Що ще треба заповнити (відкриті питання з ТЗ)

- Контакти компанії — `content/contacts.json` (зараз заглушки).
- Ціни в грн — `content/uk/pricing.json` (зараз ≈ курс до $600 / $1000 / $1500, перевірити).
- Блок «Звучить знайомо?» та заголовок hero — чернетка, чекає окремої сесії.
- Два напрямки (блок 5) — зараз «Новий сайт / Вже є сайт».
- Кейси — 4 заглушки; відгуки приховані (`reviews.visible`).
- FAQ 10 (неустойка) — загальна відповідь; уточнити умови.
- Юр. сторінки — чернетки з плейсхолдерами `[...]`, потрібна перевірка юристом.
- Домен — задати `SITE_URL` (зараз `https://teamdor.studio`).
- Ілюстрації — зараз векторні ізометричні заглушки в стилі бренду; ШІ-ілюстрації можна підставити замість них.
